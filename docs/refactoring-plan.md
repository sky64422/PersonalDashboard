# 프로젝트 리팩터링 설계 및 실행 계획

## 목적과 제약

기존 기능, DOM/CSS 계약, 키보드 조작, 검색 결과 순서와 저장 데이터 형식을 유지하면서 중복과 결합을 줄인다. React/Tauri 및 기존 의존성을 유지한다. 저장 키는 `friday.todos.v4`, `friday.hidden-task-ids`, `folio.theme` 그대로 사용한다. 새 기능이나 시각 디자인 변경은 포함하지 않는다.

단순 파일 이동만으로는 중복이 남고, 전역 상태 라이브러리 도입은 현재 규모에 불필요하다. 기존 피처 구조 안에서 책임을 분리하고 실제로 반복되는 처리만 통합한다. Rust 호스트는 창 초기화만 담당하므로 불필요한 계층을 추가하지 않는다.

## 작업과 성공 기준

- [x] 기준선: 단위 테스트, UI 테스트, 프런트엔드 빌드를 실행한다.
- [x] 도메인: `todoModel.ts`의 샘플 데이터와 저장 초기화를 분리하고, 반복되는 자식 인덱스를 공통화한다. 계층 완료/이동/삭제와 샘플 초기화 계약을 검증한다.
- [x] 화면: `Todos.tsx`를 편집기, 히스토리, 홈 미리보기로 분리한다. 부모/자식 편집 행의 공통 부분을 통합한다. 기존 DOM 클래스, 접근성 이름, 포커스/검색/드래그 동작을 유지한다.
- [x] 앱: 할 일 상태·저장·명령을 `useTodos`로 이동해 App을 화면 조합에 집중시킨다. 350ms 저장 지연, 종료 시 flush, 대량 히스토리 미리보기의 저장 차단을 검증한다.
- [x] 공통 처리/데드코드: 업무·펌웨어·전역 검색의 동일한 문자열 매칭을 공통화하고, 참조 없는 TypeScript 테마 토큰을 제거한다. CSS 테마는 유지한다.
- [x] 검증/인계: 전체 단위/UI 테스트, 프런트엔드 빌드, Rust 포맷, Tauri 빌드, 네이티브 화면 확인을 실행하고 아키텍처 문서를 갱신한다. diff를 검토하고 RELEASE.md를 읽은 뒤 커밋·푸시한다.

## 집중 회귀 항목

- 편집 직후 페이지 종료 또는 다른 즉시 저장 명령 실행 시 최신 값 보존.
- 부모/자식 계층 변경 후 커서 복구 및 완료 전파.
- 히스토리 월 이동/검색 전환 후 스크롤과 카드 펼침 유지.
- 대량 히스토리 미리보기에서 실제 저장 데이터 보존.
- Daylight/Midnight, 전역 검색 결과 선택, 네이티브 상세 패널 포커스 복귀.

## 실행 기록

사용자가 전체 리팩터링 및 테스트 후 커밋·푸시를 요청했으므로 위 범위 안의 구현 선택은 작업자가 진행한다. 새 의존성 및 저장 형식 변경은 없다. 전체 검증 후 하나의 동작 보존 리팩터링 커밋으로 전달한다.
